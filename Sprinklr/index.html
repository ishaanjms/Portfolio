Device Switcher

I was asked to make a small alignment adjustment. I pushed the work toward the larger problem: helping survey creators understand how their layouts would behave across devices while they were still building.

Situation: survey layouts were being designed blind

During my Sprinklr internship, I worked on Customer Feedback Management, a product area for creating, distributing, and analyzing surveys. The Survey Builder made desktop authoring straightforward, but creators had no direct control over how a survey might look on mobile, tablet, or custom device sizes. To validate a layout, they had to leave the builder, open preview, switch devices, inspect the result, return to the builder, and repeat.

Task

What I needed to achieve

The product ask was small: add an alignment option so survey media could be adjusted for mobile. My responsibility was to design that control, but I also needed to make sure the solution actually helped creators make better layout decisions.

Assigned Ask

Add a mobile alignment setting

The expected solution was a small configuration control in the right panel, without changing how creators previewed device layouts.

Underlying Issue

The control alone would not remove friction

Even with a new setting, creators would still need to leave the builder to understand whether the selected alignment worked.

Design Goal

Make layout behavior visible while authoring

I reframed the task around preview confidence: creators should be able to switch devices and judge layout decisions in context.

Action · Design Insights

Three principles guided the solution

01 · Visibility

Creators needed layout confidence, not just another setting

The main gap was not only control. It was the inability to see whether a layout decision worked across device sizes while authoring.

02 · Context

Preview belonged closer to the decision point

If users had to leave the builder to validate every device state, the alignment feature would still create a slow trial-and-error workflow.

03 · Safety

Device switching could not mutate the survey

The switcher needed to behave like a preview lens: useful for authoring, but safe for question logic, saved configuration, and respondent experience.

The shift was from “where should this media align?” to “how can creators confidently design for every device without leaving the builder?”

Action · Reframing

I turned the ask from a field into an authoring mode

Least Change

Add mobile alignment controls in the right panel

I started with the smallest version of the request: rename the current control to Web Alignment and add Mobile Alignment below it with top, between title and answer, and bottom placement options.

Stronger Direction

Add a device switcher in the builder top menu

I proposed a device switcher so creators could move between Web, Mobile, Tablet, and Custom views in the builder, making the alignment decision visible immediately.

Best Direction

Make responsive preview part of authoring

I framed the best version as a scalable preview model: the canvas should resize by device without mutating survey configuration or respondent-facing logic.

Action

How I compared the options

I presented multiple paths from least to best, so the team could compare implementation effort against the amount of friction removed for creators.

Least change

Add mobile alignment in the right bar

This solved the requested control gap, but it did not solve the bigger visibility problem because creators still had to preview elsewhere.

Action · Product Constraints

I defined what the shipped experience had to protect

Visible Control

The device toggle needed to be visible in the builder top menu across live, draft, template, and AI+ Builder surveys.

Viewport Accuracy

Web, Mobile, Tablet, and Custom modes needed to resize the canvas correctly and re-render survey components responsively.

Custom View

Custom width and height inputs needed validation limits for advanced device and kiosk-style preview scenarios.

No Data Mutation

Switching views could not change survey configuration, question logic, or saved respondent-facing behavior.

Configuration Parity

Web Alignment and Mobile Alignment needed to persist through save, clone, duplicate, sandbox, and porting workflows.

Permission Model

The new controls needed to follow the same permissions already applied to the existing alignment switcher.

Result

The strongest version was shipped

Moved beyond the original ask

The work evolved from a small alignment setting into a shipped device-switching experience that made layout behavior visible inside the builder.

Reduced authoring friction qualitatively

Creators no longer had to rely only on a separate preview flow to reason about web, mobile, tablet, and custom survey layouts while making changes.

What I learned

I learned to treat a small feature request as a signal. The useful design move was not just adding a setting, but finding the workflow friction behind it and proposing a solution that still fit product constraints.
